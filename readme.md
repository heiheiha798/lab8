SRAM模型本身是“读地址后，下一个周期数据有效”的同步SRAM。这通常意味着读取一个数据需要 1个周期的延迟。
Testbench代码 tb_sram_c_raddr_B = ...; @(posedge clk); @(posedge clk); 在设置地址后，第一个 @(posedge clk) 是地址设置并等待SRAM内部处理的周期，第二个 @(posedge clk) 是数据有效后TB进行采样的周期。
所以，Testbench的这种写法是正确地为这种1周期延迟的同步SRAM模型设计的。从TB发出一个读请求（设置地址）到TB得到数据，总共消耗了 2个TB时钟周期 的时间流逝。
周期T0: TB设置地址。
周期T1: SRAM内部处理，数据在T1结束时输出到 rdata_B。TB等待。
周期T2: TB采样 rdata_B。
所以，这不是Testbench设置的问题，而是正确地匹配了SRAM模型的行为。 如果SRAM是组合逻辑读（地址变化，数据立刻变化，不常见于真实SRAM），或者有不同的流水线级，TB的读方式才需要改变
