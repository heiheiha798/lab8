# **设计报告：矩阵乘法加速器 **

## **项目目标**

设计并验证一个基于脉动阵列的硬件加速器，用于高效执行矩阵乘法 C = A * B。本项目重点评估加速器核心 (`accelerator.v` 及其直接依赖的计算和局部存储单元) 的功耗、性能和面积 (PPA)，并根据指定的评分公式进行优化。输入数据和最终结果存储于外部主存（不计入PPA），加速器内部使用 Tile SRAM（计入PPA）进行数据缓存。

## **系统架构概述**

*   **顶层模块 (`accelerator.v`):** 包含一个有限状态机 (FSM) 用于控制数据流和计算流程，通过分块 (Tiling) 策略处理大矩阵。它管理两个片上 Tile SRAM (用于缓存A和B的当前数据块) 的接口，并驱动一个脉动阵列。
*   **计算核心 (`systolic_array.v`):** 参数化的脉动阵列，由 N x N 个处理单元 (PE) 构成。
*   **处理单元 (`pe.v`):** 执行基本的乘积累加 (MAC) 操作。
*   **数据格式:** 输入/输出主存数据为 SINT8，内部 Tile SRAM 和 PE 计算使用 SINT8 (根据你提供的 `accelerator.v` 和 `pe.v` 参数)。
*   **SRAM:** 两个 Tile SRAM，其参数根据 `TILE_DIM_SYSTOLIC` 从 `SRAM_available_specs` 中选择。

## **关键参数与综合环境**

*   **标准单元库:** Nangate 45nm (假设，基于 `yosys-sta` 和 `CLKGATE_X1` 的使用)
*   **综合工具:** Yosys + ABC (通过 `yosys-sta` Makefile 流程)
*   **STA 工具:** OpenSTA (通过 `yosys-sta` Makefile 流程)
*   **目标时钟频率:** 100 MHz (周期 10 ns)
    *   *(注：根据STA结果，设计有潜力运行在更高频率，但此处按100MHz计算执行时间和功耗报告。如果选择更优时钟，需重新进行STA和功耗分析)*
*   **仿真器 (用于获取执行时间):** Verilator (RTL仿真)

## **PPA 和 Score 结果**

**评分公式:** Score = `exp(SSE/C0) * Power_total (mW) * Area_total (um^2) * (Time (us))^2`
(假设无损计算，SSE=0，则 `exp(SSE/C0) = exp(0) = 1`)

### **配置 1: 全局矩阵 16x16, Tile 大小 16x16**

*   **Accelerator Logic:**
    *   面积: `354117.82 um^2`
    *   功耗: `59.63 mW`
*   **Tile SRAM (2 x No. 3: 32words x 64io):**
    *   单个面积: `1081.200766 um^2`
    *   单个功耗 (@100MHz): `1.07918055 mW`
*   **总计:**
    *   总面积: `354117.82 + 2*1081.200766 = 356280.221532 um^2`
    *   总功耗: `59.63 + 2*1.07918055 = 61.7883611 mW`
*   **执行时间 (来自RTL仿真):** `17435 ns = 17.435 us`
*   **时序:** 满足 @100MHz (WNS Setup ≈ 8.87ns)
*   **Score 计算:**
    *   `Time^2 = (17.435)^2 = 303.979225 us^2`
    *   `Score = 61.7883611 * 356280.221532 * 303.979225`
    *   **Score ≈ 6.691 x 10<sup>9</sup>**

## **结论与分析**
（这部分你可以根据你的最终目标和观察到的趋势来写）

*   本设计成功实现了一个参数化的脉动阵列加速器。
*   通过综合和STA，验证了在100MHz时钟频率下，不同配置均能满足时序要求。
*   执行时间分析表明，总执行时间与全局矩阵大小 M 呈近似 M<sup>3</sup> 的关系，与 Tile 大小 N 的关系则更为复杂，受到数据加载/存储和SA feed开销（与N<sup>2</sup>相关）以及外层循环次数（与(M/N)<sup>3</sup>相关）的共同影响。
*   对于128x128的全局矩阵计算，采用16x16的Tile配置比32x32的Tile配置获得了更优（更低）的Score，这表明在该设计和评分标准下，较小Tile带来的控制逻辑和SRAM的面积/功耗优势，超过了其执行时间较长的劣势。
*   随着全局矩阵大小增加到512x512，执行时间急剧上升，导致Score也大幅增加，符合预期。
*   设计具有进一步优化的潜力，例如通过更积极的时钟频率选择（基于较大的时序裕量）或通过流水化数据加载与计算来减少总执行时间。
