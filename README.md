初步SRAM选择和设计方向（以平衡为目标）：
A和B矩阵存储:
使用 16个 编号56的SRAM宏 (2048 words x 64 bits)。
RAM控制器负责将逻辑上连续的 32768x64 地址空间映射到这16个宏。
加速器FSM仍然与一个逻辑上的64位宽、32768字深的RAM交互（通过RAM控制器）。
假设RAM控制器的设计目标: 尽量保持对加速器的1周期或2周期读延迟。
C矩阵存储:
使用 8个 编号71的SRAM宏 (32768 words x 32 bits)。
RAM控制器职责:
当加速器要写入一个64位的C数据（包含两个SINT32）到逻辑C地址时，RAM控制器将其拆分：
低32位写入一个由4个编号71宏组成的32位宽、131072字深的存储体（例如Bank0）。
高32位写入另一个由4个编号71宏组成的并行存储体（例如Bank1）。
这两个32位写操作可以并行进行，如果SRAM宏支持。
这意味着加速器仍然认为它在和64位宽的RAM交互写C，但实际上RAM控制器在后台做了拆分。
读C的操作（如果需要）则相反，需要合并。
这种方式的好处:
C的SRAM PPA显著降低。
加速器FSM的主要数据通路（A, B加载，以及对C的写入接口）可以保持64位宽，简化FSM。
挑战: RAM控制器在处理C的写操作时需要额外的逻辑。
